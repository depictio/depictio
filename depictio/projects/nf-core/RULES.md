# nf-core template dashboard rules

The rules every `depictio/projects/nf-core/<pipeline>/<version>/dashboards/*.yaml` follows.
`ampliseq/2.18.0/dashboards/base.yaml` is the reference implementation: when a rule below
leaves room for doubt, do what it does.

The authoring features these rules use (tab groups, block markdown, highlights, card
variants, filter bars, `category_colors`, docked controls, autofit) are documented in the
depictio docs (`features/dashboards.md`, `features/yaml-sync.md`). The markdown grammar a
text tile accepts is `packages/depictio-react-core/src/components/markdownCheatsheet.ts`.

## 1. Sources and checks

- `dashboards/base.yaml` is generic: it names template variables (`{GROUP_COL}`,
  `{METADATA_ID_COL}`, ...) and never a value from one run. A reference or demo layer on top
  of it is generated by a script (`build_reference_dashboard.py`), never hand-edited.
- Before committing a template, run:
  - `python -m depictio.cli dashboard validate <yaml> --offline`
  - `pytest depictio/tests/models/test_template_conventions.py depictio/tests/models/test_shipped_dashboard_yamls.py -k <pipeline>`
- Then import it on a running stack and look at every tab (section 14).

## 2. The family of tabs

- The main tab is the **Overview**: `main_tab_name: Overview`, and the family keeps
  `title: nf-core/<pipeline>`.
- The MultiQC report is a child tab named exactly `MultiQC`. It holds MultiQC panels only
  (the lint checks it): no card strip, no figures from the pipeline's own outputs. A
  pipeline without a MultiQC report has no such tab.
- Child tabs carry a `tab_group`. The first group is always `Data & QC` (MultiQC, sample QC,
  sampling campaign, sample sheet). Then one or two analysis groups named for the pipeline,
  at most two words each and at most five tabs each (ampliseq: `Diversity`, `Taxa`).
- `tab_order` is contiguous within a group, groups in reading order: broad to narrow, the
  analytical funnel.
- Every child tab has a `subtitle` of at most 12 words saying the question it answers
  ("How diverse is each sample?").

## 3. The Overview

At most **24 grid rows** at compact width, in this order:

| Block | Section | Content | Size |
|---|---|---|---|
| Hero | none | one text: `title: nf-core/<pipeline>`, its wordmark as `logo:` (and `logo_dark:`) when `depictio/api/static_assets/images/workflows/` ships it, one sentence on what the run is, a `[Run parameters](params:)` link | w8 h1 |
| About | none | two `surface: card` texts side by side: `### About this dashboard` (what it shows, how to use it) and `### The run` (an icon list of run facts from `{{param:…}}` and `values:`) | w5 h3 + w3 h3 |
| Pipeline | none | a `surface: card` text with `accent: <colour>`: a `###` heading, one intro line, then a `::: steps` flow of 4 to 6 icon-led steps, each with `params:` and `tab:` links | w8 h3 |
| Key figures | `appearance: plain`, `card_variant: headline`, `filter_bar: true`, `visible_filters: 2` | at least 2 filters (the group, then the sample), then 4 cards, each with `caption`, `link: tab:<Tab>` and a `description` | 4 × w2 h2 |
| Findings | `appearance: plain`, `figure_style: minimal`, `filter_bar: true`, `visible_filters: 2` | a findings text with live `values:` (w8 h2, `surface: card`), then 4 figures, one per analysis tab, in 2 rows that each fill the width | text w8, then w5 + w3 and w3 + w5 |
| How to read | `appearance: plain` | one text: a `###` heading per tab group, then a `-` list of tab tiles `[Tab](tab:Tab): question` | w8 h2 |

```yaml
main_dashboard:
  title: nf-core/<pipeline>
  main_tab_name: Overview
  tab_icon: mdi:compass-outline
  filter_panel_default: collapsed
  content_width_default: compact
  show_tab_header: false
  category_colors:
    "{GROUP_COL}": auto
  grid_sections:
    - {name: Key figures, appearance: plain, card_variant: headline, filter_bar: true,
       icon: mdi:counter, color: gray, description: "The run in four numbers. The filter here narrows these four only."}
    - {name: Findings, appearance: plain, figure_style: minimal, filter_bar: true, visible_filters: 2,
       icon: mdi:star-outline, color: gray, description: "What the data says, each with the tab that shows it."}
    - {name: How to read this dashboard, appearance: plain, icon: mdi:information-outline, color: gray}
    - {name: Sample sheet, persistent: true, pin: bottom, collapsed: true,
       exclude_tabs: [Overview], icon: mdi:table-account, color: gray}
  filter_sections:
    - {name: Sample filters, persistent: true, pin: top, icon: mdi:filter-variant, color: teal}
```

- **Two filter levels on the Overview, on purpose.** The filter bar of a section narrows that
  section only (its description says so). The persistent `Sample filters` in the left panel
  narrow every tab; the panel starts collapsed on the Overview.
- **Key figures**: one card per stage of the funnel (samples, the core measure, the main
  result, a QC rate). Pick secondaries that say something about the number:
  `composition` by a categorical column, `box_plot` for a per-sample measure, `coverage`
  for a share of a known total.
- **Findings text**: 3 or 4 result rows, each a live value, a claim and a link to the tab
  that shows it. Values come from the `values:` block (section 9). Do not state a number a
  run may contradict; state the measure and let the value fill in.
  ```yaml
  - component_type: text
    surface: card
    values:
      top: {dc: taxonomy_rel_abundance, column: Phylum, aggregation: top, weight: rel_abundance}
      top_share: {dc: taxonomy_rel_abundance, column: Phylum, aggregation: top_share, weight: rel_abundance, format: percent}
    body: |
      - **{{top_share}}** of reads are {{top}}, the dominant phylum [Community](tab:Community & Diversity)
  ```
- **Highlights** redraw a figure or an advanced viz of another tab with the Overview's
  filters, in the minimal style: no controls on the tile, a caption under it. The source is
  named by its `index`:
  ```yaml
  - component_type: highlight
    section: Findings
    source_tab: Ordination & Clustering
    source_component: ord-embedding
    caption: One point per sample; the closer two points, the more alike their communities.
    layout: {x: 0, y: 7, w: 3, h: 5}
  ```
  A highlight cannot show a MultiQC panel, a card or a table.
- **Simplified figures**: where the child tab's figure is too dense for a third of the row,
  draw a summary of it instead of a highlight. The tree summed by rank is one: an
  `advanced_viz` with `collapse_rank`, `top_n` and `size_by: abundance`, its dots split by the
  group (`abundance_split_col: '{GROUP_COL}'`), with `link: tab:<Tab>` and a caption.
- **Each figure says something the Key figures do not.** A per-group box of the measure a
  card already shows (the Shannon card, then a Shannon box) repeats it; prefer the tab's
  result (the volcano, the ordination). Figures share one header style: title, the linked
  tab's icon, no icon badge of their own.
- **Findings rows fill the width.** Two rows of 8 columns, a wide and a narrow tile in each,
  swapped on the second row (w5 + w3, then w3 + w5) so the eye zigzags. The tiles of one row
  share a stored `h`: give both the height the taller one autofits to (an advanced viz
  summary grows to its rows), or the next row starts ragged.

## 4. Child tabs

- First section: a **KPI strip**, boxed and open, `card_variant: compact`, 4 cards w2 h1 (or
  2 cards w4 h1). Never 3 cards on a 4-slot row. The MultiQC tab has none.
- Then at most **3 open** detail sections.
- Then the collapsed ones: tables, per-sample details, alternate-route sections.
- No intro text per section: the section `description` (one sentence, at most 90 characters)
  says what it shows. At most one short intro text per tab, and only when the subtitle is not
  enough.
- Order inside a tab: cards, then distributions, then detail, then tables.

## 5. Card styles by context

| Where | `variant` (or section `card_variant`) | Secondary layouts |
|---|---|---|
| Overview Key figures | `headline`, with `caption`, `link`, `description` | `composition`, `box_plot`, `coverage` |
| Child KPI strip | `compact` | `composition`, `coverage` (others are not drawn at this size) |
| Detail sections | `default` | any, with its required fields |

- The icon is the watermark on the right. Never `icon_style: badge`.
- No legacy styling keys: `title_color`, `title_font_size`, `value_font_size`. Cards without an
  `icon_color` take their section's colour.
- `top_n` only under an aggregation with a per-group meaning; a percentage column is not
  averaged without a `filter_expr` (lint rules b and f).

## 6. Filters

- **Child tabs filter from the left panel only**: the pinned persistent `Sample filters` (sample
  id and the design columns from `METADATA_FILE`), plus at least one open, tab-local
  `filter_sections` entry on a column of the tab's own data collections. A tab without a
  filter is a defect. Each persistent filter must reach the tab's data through a link.
- Every filter has an icon and a colour: `display: {icon_name: mdi:…, custom_color: <Mantine
  palette name>}`. A column keeps its colour on every tab (the group `violet`, the sample id
  `teal`, taxonomy `grape`...); without one the filter falls back to the brand blue.
- Filter bars (`filter_bar`) appear on the Overview only, with at most 2 visible controls, each
  with a short `strip_label`. Never `display: strip`.
- Put the group filter (`{GROUP_COL}`) first among the Overview's filters: the Guide demos the
  first categorical filter it finds.

## 7. Colours

- `category_colors` is declared once, on the main tab; child tabs inherit it.
  - Known vocabularies are written out (taxonomic kingdoms, pass/warn/fail, variant classes...).
  - The group column takes `"{GROUP_COL}": auto`: the server gives each of its values a colour
    from a colour-blind-safe palette at import, and keeps them on a re-import.
  - `{"*": auto, control: "#868e96"}` pins some values and fills the rest.
- No per-figure colour map (`color_discrete_map`, `set_colors`, `col_annotation_colors`) for a
  column `category_colors` already covers. UI figures, advanced viz, maps and filter chips all
  read it.
- Code figures read the same colours, and follow Analysis mode's groups when it has some. With
  grouping on, `depictio_group_kwargs` holds `color`, `color_discrete_map` and `category_orders`,
  so a figure either spreads it (and names no colour of its own) or takes the pieces, never both:
  the spread would pass `color` twice.
  ```python
  # Colours by the group column: the groups' column and colours when grouped.
  grp = depictio_group_by[0] if depictio_group_by else "{GROUP_COL}"
  colors = (
      depictio_group_kwargs.get("color_discrete_map")
      or depictio_category_colors.get("{GROUP_COL}")
      or {}
  )
  fig = px.box(df.to_pandas(), x=grp, y="shannon", color=grp, color_discrete_map=colors)
  # Colours by nothing else: spread the kwargs.
  fig = px.scatter(df.to_pandas(), x="dim_1", y="dim_2", **depictio_group_kwargs)
  ```
  A figure that aggregates groups by `[*depictio_group_by, ...]` so the group column survives.
  Guard a group column that the no-metadata route removes: `if grp in df.columns`.
- No hardcoded colours anywhere else (Mantine palette names in `icon_color` and section colours).

## 8. Viz controls

- Advanced viz controls dock by width: right of a tile that takes the whole row (and at least
  720 px), above a narrower one (at least 300 px), behind the icon below that.
- So: never set `advanced_viz_controls` (dashboard) or `config.controls_placement` to `header`
  or `rail`, and leave the component's `controls_placement` unset.
- Advanced viz tiles are `w: 8` (controls on the right) or `w: 3` to `w: 7` (controls on top).
  Never `w <= 2`.
- Minimal tiles and highlights on the Overview keep their controls behind the icon, by design.

## 9. Live values in text

```yaml
values:
  <name>: {dc: <data_collection_tag>, column: <col>, aggregation: <agg>,
           weight: <col>, filter_expr: "<expr>", format: percent|integer|si|decimals:N}
```

- Names are lowercase snake case, at most 12 characters (`top_share`, `n_sig`): the template
  variable syntax `{UPPER}` must never match them.
- `aggregation` takes the card aggregations plus `top` (the category with the largest summed
  `weight`, or the most rows) and `top_share` (its share of the total, a fraction).
- `{{param:<key>}}` prints a pipeline parameter of the run (`{{param:dada_ref_taxonomy}}`).
- Values follow the tab's filters, like cards. An unavailable value prints "–".
- Each value line must survive alone: at import, a line whose value's data collection is
  missing is removed.

## 10. Heights and autofit

The stored `h` is a floor, not a size: the viewer autofits text, cards, tables and advanced
viz to their content. Never write `fit: fixed`.

| Type | Stored `h` |
|---|---|
| text | the estimate of `depictio/models/components/text_layout.py` (the lint checks it) |
| card | headline 2, compact 1 |
| table | 6 (tables only shrink) |
| figure | 4; add `layout: {fit: auto}` only to a bar, box or violin whose category axis is short (groups, not samples) |
| advanced viz | 5 for kinds that report their height (heatmaps, stacked taxonomy, UpSet, DA bars, record card), 6 otherwise |
| MultiQC panel | 4 |
| highlight | 4 |

- Tables are full width (`w: 8`), except beside their linked record card (`w: 5` + `w: 3`).

## 11. Height budget

- The Overview: at most 24 rows.
- A child tab: at most **20 rows of sections open by default**. Everything else is in sections
  that start collapsed: details, tables, alternate routes, the sample sheet.

## 12. Guide prerequisites

The dashboard Guide demos the dashboard's own components. It finds what it needs when:

- the main tab has a card and a categorical filter on the same data collection (the group
  filter, listed first);
- a child tab has a boxed (not `plain`) section holding cards;
- some tab has a selectable figure (`selection_enabled` + `selection_column`) or a
  row-selectable table;
- code figures spread `depictio_group_kwargs`;
- some text links a tab (`[Tab](tab:Tab)`).

## 13. Conditional routes and pruning

`template.yaml` prunes data collections per route (no metadata, alternate classifier, skipped
step). Text, highlights and links bind no data of their own, so:

- route alternates (the same card from two classifiers) share one grid slot;
- a highlight's source needs a semantic `index` (at most 30 characters, a few hyphens); the
  import drops a highlight whose source is gone;
- unprunable text (hero, steps, how to read) names no `{VARIABLE}`: an unresolved one would
  print its braces;
- `values` lines are pruned one by one, with their data collection.

## 14. Prose

- No em dashes. Result rows separate claim and context with " – ".
- Block markdown (lists, headings, `:::`, tables) uses `body: |`, one line per paragraph or
  item. A prose-only body uses `body: >` so it reflows to the tile.
- At most 3 sentences per paragraph (the lint counts prose, not list items).
- No raw column names on axes. Code figures pass `labels=` (`{"dim_1": "PCo1"}`) or set the
  axis titles; an embedding takes `axis_prefix` (`PCo` gives PCo1 / PCo2).
- No megatest sample names, genes or loci: the sibling `megatest.yaml` `forbidden_terms` are
  checked in every title, description, body, caption and value filter.
- Icons come from the bundled sets (`mdi:` mostly); section icons and colours from
  `depictio/viewer/src/components/sections/sectionIcons.ts`.

## 15. Live check before a template is done

On a running stack, with the template ingested from its megatest data:

- the Overview fits in about two screens, values fill in, highlights draw, `tab:` links open;
- controls dock right on full-width viz and on top of narrower ones;
- no tile shows an empty band (autofit) or a cut body;
- the group has the same colour on figures, advanced viz, the map and the filter chips;
- the Guide's demos are not empty;
- each conditional route still renders without a broken highlight or a stray `{VAR}`.
