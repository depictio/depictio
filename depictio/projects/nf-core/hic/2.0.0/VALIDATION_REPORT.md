|---|---|

## Discrepancies

### HC-D1: `megatest.yaml` shipped with 4 dead keys

The manifest guessed `hicpro/*.mapstat`, `*.pairstat`, `*.RSstat`,
`*.mergestat` at the top level; the real files are nested under
`hicpro/stats/<sample>/` with different extensions (`.mmapstat`,
`.mpairstat`, `.mRSstat`, no `.mergestat` equivalent at all). Fixed by
removing the 4 dead keys, the existing `hicpro/stats/*` entry already covers
everything via `fnmatch`'s `.` crossing path separators.

### HC-D2: MultiQC `plots:`/`selected_plot:` is the section name, not the plot title

Confirmed via the installed multiqc 1.35 package source
(`multiqc/modules/{hicpro,fastqc}/*.py`, grepped for `add_section(name=...)`
vs `"title":` config): the value that resolves at runtime
(`extract_multiqc_metadata()`, keyed by bare `section.name`) is a different
string from the plot's internal `title` config (e.g. section name "Read
Mapping" vs. plot title "HiC-Pro: Mapping Statistics"). `template.yaml`'s
`plots:` field is itself decorative/unvalidated (`DCMultiQC` is a permissive
model) but was still authored against the correct value to keep docs and the
dashboard's `selected_plot:` in sync with what actually renders.

### HC-D3: catalog `roles:` should carry only REQUIRED roles; optional roles go in dashboard `config:`

Confirmed via viralrecon's mosdepth `coverage_track` usage and
`mosdepth/genome_coverage.yaml`: `roles:` at the catalog level binds only the
kind's required roles; optional roles (`end`, `sample`, `category`, etc.) are
set per-dashboard via `config: {<role>_col: ...}`. Initially over-specified
`roles:` in `eigenvector.yaml`, `insulation.yaml` and `contact_matrix.yaml`
with optional roles included; narrowed to required-only and moved the
optional bindings to the dashboard's `advanced_viz.config`.

### HC-D4: render-id collision with the derived output short-id

`cooler/contact_matrix.yaml`'s `advanced_viz` render was first given the
explicit `id: contact_matrix`, which collides with the output's own derived
short-id (`"cooler_contact_matrix".removeprefix("cooler_")` = `contact_matrix`)
,  `_load_tool_dir` raises `ValueError` on this. Renamed the render id to
`binned_contact_map`; `use: cooler/binned_contact_map` in the dashboard
reflects the rename (the `card`/`table` renders, which resolve via the
output's own id, kept `use: cooler/contact_matrix`).

### HC-D5: `nf_core_url` requires `github.com/nf-core/modules/...`; pipeline-local modules need `source_url`

`hicexplorer/module.yaml`'s module (`HIC_PLOT_DIST_VS_COUNTS`) is a
pipeline-local module in `nf-core/hic`, not a shared `nf-core/modules` entry.
`_check_identity_urls()` enforces the `github.com/nf-core/modules` authority
on `nf_core_url` specifically; switched the field to `source_url` (no
authority check).

### HC-D6: `int64`/`float64` columns cannot use `Select` as an interactive widget

`INTERACTIVE_COMPATIBILITY["int64"]` is `["Slider", "RangeSlider"]` only ,
`Select` is not permitted on numeric columns (it is for
`category`/`object`). Three filters (`hc-cp-filter-resolution`,
`hc-td-filter-window`, `hc-td-filter-resolution`) were originally authored as
`Select` on `int64` resolution/window columns; switched to `RangeSlider`.

### HC-D7: `ProfileConfig`/`ContactMapConfig` field names differ from a first guess

`ProfileConfig` uses `log_x`/`log_y` (not `x_scale`/`y_scale: log`).
`ContactMapConfig` uses `count_col` (not `value_col`) and British-spelled
`colour_scale` (not `colorscale`), whose `Literal` values are `Viridis`,
`Plasma`, `Inferno`, `Magma`, `Cividis`, `RdBu`, `Spectral` (`"Reds"` is not
valid). Both were caught only by direct inspection of
`depictio/models/components/advanced_viz/configs.py`, since the config
submodels are `extra="forbid"` and give no partial-match diagnostics beyond
"Extra inputs are not permitted".

### HC-D8: schema union at ingest is null-fill, not strict concat

`cooltools/insulation.py` initially assumed a fixed 3-window tuple; the real
run's two resolution files (20 kb, 40 kb) scan *different*, only
partially-overlapping window sizes (300k/500k/1M vs 600k/1M/2M).
`align_lazy_schemas()` (the real ingestion path for a recursive `Table` scan)
unions columns across all matched files and null-fills missing ones per file,
then does a default `pl.concat()`: files with genuinely different column
sets still concatenate successfully via null-fill, not via strict/error
matching. The recipe was rewritten to discover windows dynamically from
`df.columns` and to filter on `n_valid_pixels.is_not_null()` (not
`log2_insulation_score`) to correctly distinguish "this file never scanned
this window" (null) from "this bin is masked at a window that WAS scanned"
(a real `0.0`).

### HC-D9: five concurrent agents transiently broke the shared catalog directory during this session

`load_catalog_entries()` is `@lru_cache(maxsize=1)` and eagerly loads/
validates every tool folder under `depictio/catalog/`: a single malformed
file anywhere in the catalog breaks catalog loading (and therefore
`AdvancedVizLiteComponent` validation) for every pipeline sharing the
worktree, not just the owner. During this session, `bcftools`, `cellbender`,
`cellranger`, `qualimap` and `samtools` tool dirs were each observed broken
at various points (built concurrently by other agents in the same lot-2
worktree) and blocked `test_catalog.py`/`test_shipped_dashboard_yamls.py`
globally; all had been fixed by their owning agents by the time this report
was written, and the full suite now runs clean except for the two
model-schema-staleness failures noted above. Recommend the brief mention this
collision risk explicitly (isolate `_load_tool_dir` validation per own tool
dir as a workaround when the shared suite is red) for the next 6 pipelines.

### New catalog outputs under `cooltools`

| Output | Rows | Renders |
| --- | --- | --- |
| `cooltools/distance_profile` | 670 (22 series, at most 33 points each) | `ps_curve` + `ps_slope` profiles, 2 box-plot cards, table |
| `cooltools/domains` | 43,775 | `domain_track` (genome_view, rect), `domain_size_track` (coverage_track), box-plot / top-N / gauge cards, table |

`distance_profile` recomputes P(s) from the balanced `cooler dump` triplet and
its bins (the same two raw scans `cooler/contact_matrix.py` reads). The
denominator at separation `s` is every bin pair that could have been observed
(`n_bins(chrom) - s`), not the non-zero pixels the sparse dump wrote;
dividing by observed pixels flattens the tail exactly where the matrix gets
sparse. Separations are pooled into 40 log-spaced bins with sums on both
sides, and `log10_slope` is the finite-difference derivative along that binned
curve. The pooled curve reads -1.53 at 1 Mb and steepens past -2.4 beyond
100 Mb, which is the expected mESC shape.

`domains` derives TAD intervals from `is_boundary_<window>`. Runs of adjacent
flagged bins are merged into one boundary region first (a boundary at 20 kb is
usually 2-3 bins wide); a domain is then the span between the end of one
boundary region and the start of the next, within one cooltools `region` so no
domain crosses a scanned-region gap. Each domain is scored on the share of its
bins that are mappable, and a domain below 0.5 is dropped.

| resolution | window | domains | median size | max size |
| --- | --- | --- | --- | --- |
| 20 kb | 300 kb | 11,337 | 160 kb | 2.52 Mb |
| 20 kb | 500 kb | 9,559 | 180 kb | 2.84 Mb |
| 20 kb | 1 Mb | 8,256 | 200 kb | 5.20 Mb |
| 40 kb | 600 kb | 5,312 | 360 kb | 2.48 Mb |
| 40 kb | 1 Mb | 4,803 | 360 kb | 5.84 Mb |
| 40 kb | 2 Mb | 4,508 | 360 kb | 12.60 Mb |

Without the mappability filter the maximum at 20 kb / 300 kb is 30.84 Mb, an
unmappable stretch reported as a single TAD.

## Discrepancies

### HC-D10: the published distance-decay curve is 13 points, not a curve

`hicPlotDistVsCounts` ran with a 3 Mb depth cap on the 250 kb matrix and wrote
13 rows, all `Chromosome == all`. It cannot show the knee, cannot be split per
chromosome and cannot be compared between conditions. `cooltools expected-cis`
never runs in nf-core/hic 2.x. This is why `cooltools/distance_profile.py`
recomputes P(s) from the contact dump rather than binding the published curve;
the published one is kept on a collapsed section for comparison.

### HC-D11: cooltools calls boundaries, hicFindTADs never runs

`HICEXPLORER_HICFINDTADS` is absent from `pipeline_info/execution_trace_*.txt`,
so no interval list of TADs exists on disk at any nf-core/hic 2.x version. The
domains here are derived, and the derivation is a choice, not a ground truth:
merging adjacent boundary bins and requiring 50% mappability are both
parameters of this recipe, documented in its module docstring. A reader
comparing these domain counts with a published mESC TAD set should expect the
insulation-window choice to dominate the difference (11,337 domains at a
300 kb window against 8,256 at 1 Mb, same data).

### HC-D12: no samplesheet factor exists, so the persistent section holds one filter

The maintainer rule asks for one persistent filter per real samplesheet factor.
`samplesheet.valid.csv` has `sample` (1 value), `single_end` (1 value, False)
and the two FASTQ paths (3 values each, file paths rather than factors), and
the `samples` hub has `sample_id`, `n_libraries` and `single_end`, all
single-valued. There is no factor to expose. Every tab therefore carries the
sample filter plus a tab-local section on its own collections' categorical
columns (mapping fate, contact fate, chromosome, compartment, window,
resolution), which are the columns with 2 to 23 real values on this run.

### HC-D13: the shared catalog is still all-or-nothing under parallel agents

`load_catalog_entries()` validates every tool folder under
`depictio/catalog/`, so one half-written dir anywhere breaks
`AdvancedVizLiteComponent` validation for every pipeline. During this pass
`ascat/`, `gtdbtk/` and `mag/` were each observed broken (other agents, same
worktree). Validation of the hic tiles was therefore also run against a copy
of the catalog with the broken dirs removed, where all 15 `advanced_viz`
tiles resolve their `use:` and survive the component union with zero errors.
The two red tests above are expected to go green once those agents land.

### HC-D14: the `genomespy_track` kind was renamed to `genome_view` mid-session

The brief named the kind `genomespy_track`, and
`depictio/models/components/advanced_viz/configs.py` still spelled it that way
early in this session; by the time the catalog entries were validated,
`types.py` and `configs.py` had been renamed to `genome_view` by the kind's
owning agent. All three locus tracks bind `genome_view`. The config also gained
`mark: bar`, `sample_col`, `category_col`, `facet_by_sample`,
`annotation: none|hg38|mm10` and the region-brush pair
(`region_filter_enabled` / `follow_region_filter`) relative to the brief; the

### HC-D15: `.cool` files remain unreadable, and that is still the right call
