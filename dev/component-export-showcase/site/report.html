Using Depictio's own control instead

The controls above were rebuilt in this site's idiom from the manifest's filter contract. The alternative is to embed Depictio's real widget as format=html and listen for what it posts out. Both paths end at the same filters= array on the export URL, so a host chooses how much of Depictio's interface it adopts, not whether it can use the data.

How the binding works

Each control names a column, and the export manifest publishes which interactive component drives which column, along with its option list. So the deck is never hard-coded against the data: if a column has no control on the dashboard, the deck omits it rather than rendering a widget that filters nothing. A filter is only sent to figures whose data collection actually has that column, because this dashboard spans several collections and a filter naming habitat is meaningless to the taxonomy table. When a filter reaches nothing, the response says so and the panel reports it.
